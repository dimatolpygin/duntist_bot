# Второй бот

Первый бот остаётся в `/opt/zarub_bot`, второй подготовлен в `/opt/zarub_bot_second`.
Оба подключаются к `zarub_bot_default`. Новые PostgreSQL/Redis и открытые порты не нужны.

| Параметр | Первый | Второй |
|---|---|---|
| Compose-проект | zarub_bot | zarub_bot_second |
| Схема PostgreSQL | zarub | zarub_second |
| База Redis | /0 | /1 |
| S3-префикс | orders | orders-second |
| Текст предупреждения | на следующее утро | на следующий день до 12:00 |

Второй экземпляр — копия логики, настройки различаются. Фраза про STL информационная,
проверка расширения файлов не добавлялась. Номера заказов начинаются независимо.
Разделение схем/Redis — логическое разделение данных, общая инфраструктура остаётся общей.

Команды внутри `/opt/zarub_bot_second`:

```sh
# Повторная проверка и миграции только второго экземпляра:
docker compose -f docker-compose.second.yml run --rm --no-deps bot_second python -m src.prepare_second

# Запуск только после этапа 7, заполнения доступов и проверки новой группы:
docker compose -f docker-compose.second.yml --profile second up -d --no-build
docker compose -f docker-compose.second.yml logs --tail=50 bot_second

# Остановка только второго экземпляра:
docker compose -f docker-compose.second.yml stop bot_second
```

В `.env.second` — обычные строки `KEY=value` без кавычек: Compose читает `format: raw`,
чтобы символы `$` в секретах не интерполировались. Не выводить файл в логи.
При повторном подключении меняются только BOT_TOKEN/GROUP_ID, остальные настройки уже подготовлены.
Новый бот должен состоять в своей группе и иметь право отправлять сообщения и документы.
Видео при необходимости задаётся отдельно командой `/setvideo`.

## Сборка и обновления

`Dockerfile.second` использует существующий `zarub_bot-bot:latest` с установленными
зависимостями и копирует только `src/` и `migrations/`. Перед подготовкой проверяется
совпадение requirements.txt с первым контейнером. При изменении зависимостей потребуется
новый базовый образ; не собирать второй из несовместимого первого.

Сейчас второй подготовлен из `dev`; основной `master`/Actions первого бота не менялись.
Автоматическое обновление второго не подключено. Его настройка и сквозная проверка —
этап 8 после явного разрешения обновить `master`. Обычный push в dev сервер не обновляет.

Не запускать основной `docker-compose.yml` из второго каталога: он создаёт лишние БД/Redis.
Не использовать один токен для двух работающих контейнеров. Не ставить этапам теги до
подтверждения пользователя; технические проверки подготовки не заменяют UAT Telegram.
